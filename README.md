## 版本管理要求


1. **一篇文档只有一个文件，持续修改原文件**。正文文件名不写版本号，不使用空格、冒号或“最终版”；版本和日期写在文件头，历史由 Git 保存。原始附件的来源版本保留在附件名与来源登记中。
2. **文件头写全**：`title / owner / status / version / updated / summary`。每次修改同时更新版本、日期和摘要；提交说明用一句话写清改了什么。
3. **小改可直接提交 main；大改或需要别人先看的改动走分支和 PR**，对方合并后生效。
4. **状态只用草稿 / 评审中 / 定稿 / 作废**。定稿时打 Tag；作废文档保留备查，不删除原有编号。
5. **严禁 force push、严禁改写历史**。改错后从 History 取回旧内容，重新提交一次。
6. **目录用两位编号，每个目录有 README**。新内容先看能否写入已有文档；确有新主题再建文件。现有编号不重排。
7. **决定集中记录**在 `00_总览/产品现状与决策清单.md`，注明出处、责任人、日期；会议正文与专题文档通过链接引用，不各自维护相互矛盾的决策台账。
8. **改别人负责的文档先批注**，例如 `> **王兮的注释**：……`；直接修改原文前先与负责人对齐。
9. **库内链接一律用相对路径**。移动或改名文件时，同一次提交更新所有引用；图片放所属目录的 `assets/`，正文使用 `![说明](assets/图片.png)`。
10. **数字标清性质和来源**：法规值带依据编号，预估值写“估计／预估”，实测值带测试记录。预估价格旁保留“实价”列。厂家规格值注明文档版本与页码。
11. **图纸与原件保留来源**。新绘图保留 SVG 源文件和 PNG；连线横平竖直，文字不出框。原纪要图片和厂家原图按原样保存，注明来源，不凭照片估算尺寸。
12. **大文件按样板处理**：超过50 MB的PDF、视频、模型、压缩包等放项目资料存储，文档中贴链接并登记版本、校验值；不把大包反复提交进Git。


本库采用项目统一的文档维护方式。当前仅有框架与通用说明；正式公开资料以具体文件标注的状态、版本和适用范围为准。
