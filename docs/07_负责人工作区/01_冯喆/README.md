人员安排：维护人员邀请后续办理。职责来源见 [现有说明](../../00_总览/01_公开资料说明.md)；业务owner与GitHub权限分别管理。

## 从哪开始

1. [工作清单](01_工作清单.md)：本人的工作范围、关联事项及补充记录。
2. [资料与评审入口](02_资料与评审入口.md)：相关正文、评审材料和资料位置。
3. [工作区总览](../README.md)、[全库纪律](../../README.md)。

## 纪律

- 按样板使用两位编号、稳定文件名和统一文件头；修改时更新版本、日期和摘要。
- 相关专业正文在原目录持续维护；在本目录用相对链接关联。一篇文档只有一份持续更新的正文。
- 事项的当前状态、责任边界、期限和决定统一见 [集中台账](../../00_总览/产品现状与决策清单.md)；本目录引用事项编号，不另维护平行决策表。
- 改他人负责文档先加署名批注，按全库规则审阅后更新；小改可直接提交，大改或需先审阅时走分支和PR。
- 本目录新增图放 [assets](assets/README.md)，相对路径嵌入；新绘图保留SVG和PNG，原始配图注明出处。
- 定稿打Tag；作废保留；禁止force push和改写历史。
